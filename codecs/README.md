# Optional codec deployment

Glide keeps optional codec breadth completely off the ordinary cold-launch path.

Each provider consists of a native DLL and a sibling `*.glidecodec.json` manifest (`name.dll` pairs with `name.glidecodec.json`). `tools/generate-codec-index.ps1` verifies each DLL SHA-256 at build/package time and writes `codecs.index.json`. At runtime Glide reads only that tiny index when an exotic file first requires an optional provider; the selected DLL alone is then hashed, ABI-checked and loaded.

New providers should implement ABI v2 from `../native/Glide.CodecProvider.ABI.h` and return premultiplied BGRA8 decoded surfaces. ABI v1 remains accepted only for migration. A format is not release-certified merely because it appears in the 196-suffix registry: it needs a real fixture, malformed-file isolation, correct dimensions/orientation/alpha and cold/warm/navigation measurements (the format route map is in `../docs/format-coverage.md`; the headless benchmark harness is in `../tools/perf`).

Do not add eager static initializers, process-wide codec scans, helper processes at normal startup, or viewport/input changes as part of codec work.

## Bundled provider: `glidecodecs.dll`

One statically linked (including the static CRT: it imports only KERNEL32) ABI v2 provider (id `glide.codecs`), about 4.9 MB. It decodes the formats below and, since 5.0.4, also writes JPEG 2000 and WebP for Save as (the only encoders it contains):

| Suffixes | Library (pinned upstream release) |
| --- | --- |
| `.avif` `.avifs` | libheif 1.23.7 + dav1d 1.5.4 (8/10/12-bit, x86 assembly) |
| `.heic` `.heif` `.heics` `.heifs` `.hif` | libheif 1.23.7 + libde265 1.1.3 (HEVC; optional, see below) |
| `.jxl` | libjxl 0.13.0 decoder only (Highway SSE2 + AVX2, no Brotli/JPEG reconstruction) |
| `.jp2` `.j2k` `.j2c` `.jpc` `.jpx` `.jpf` `.jpm` `.mj2` | OpenJPEG 2.5.4 decoder (JPM/MJ2: first codestream only) |
| write `.jp2` `.j2k` | OpenJPEG 2.5.4 encoder (lossless 5/3, or lossy 9/7 with quality mapped to a compression ratio) |
| write `.webp` | libwebp 1.5.0 encoder (lossy with quality, or lossless), vendored in `../native/third_party/libwebp` |

- Format detection is by content (`ftyp` / JXL / JP2 / J2K signatures), not by suffix.
- HEIF `irot`/`imir` and JPEG XL orientation are applied; alpha is preserved and premultiplied; every source bit depth (10/12/16-bit, HDR) is reduced to 8 bits per channel. Sequences (AVIFS/HEIFS, animated JXL) show their primary image or first frame.
- Previews: JPEG 2000 stops the wavelet at the resolution level nearest the requested size; the other formats decode fully and are area-averaged down.
- Encoding (ABI v2 extension): capability bit `SupportsEncode` (`1u << 4`) plus the optional export `GlideCodecProvider_EncodeSurface(instance, utf8Path, const Surface*, format, quality)` (`"jp2"`, `"j2k"`, `"webp"`; quality >= 1 is lossless). Hosts that predate it ignore both, and Glide looks the export up with `GetProcAddress`, so a decode-only provider keeps working. The build script's export allow-list includes it.
- Hostile input: every call is bounded (dimension/pixel/file caps matching Glide's decode guard) and decoder hardware faults are contained so a malformed file fails instead of crashing Glide.

Files here (all generated by `tools/build-codecs.ps1`): `glidecodecs.dll`, `glidecodecs.glidecodec.json`, `glidecodecs.NOTICE.txt` (component list, exact commits and full license texts) and `codecs.index.json` (regenerated by `build.cmd`). `build.cmd` copies them to `dist\codecs`, which the portable ZIP and the installer both package. Dev runs and tests get the same files in `<output>\codecs` through `Directory.Build.props`.

### Rebuilding

```
powershell -ExecutionPolicy Bypass -File tools\build-codecs.ps1 [-NoHevc] [-NoAsm] [-Dav1dBitdepths 8] [-MapFile] [-Force]
```

Sources are fetched by pinned commit from the official upstream repositories (git verifies every object against the pinned hash), NASM is a pinned SHA-256-verified download and Meson runs from a private venv; everything is cached under `%LOCALAPPDATA%\Glide-build-cache\codecs`. Needs Visual Studio 2022+ C++ build tools, CMake, Python and git. `build.cmd` runs it automatically when `glidecodecs.dll` is missing (for example from a source handover ZIP, which carries no DLLs). The glue lives in `../native/Glide.Codecs`; tests and synthetic fixtures are in `../tests/Glide.Core.Tests/BundledCodecProviderTests.cs` and `../tests/Glide.Core.Tests/Fixtures/Codecs`.

### Licensing and patents

dav1d and OpenJPEG are BSD-2-Clause, libjxl, Highway, skcms and libwebp BSD-3-Clause (libwebp with an additional patent grant), Brotli MIT, libheif and libde265 LGPL-3.0-or-later. Because the LGPL libraries are linked statically, the glue source and build script must stay available with releases so users can relink against modified versions (see `glidecodecs.NOTICE.txt`). HEVC is patent-encumbered: `-NoHevc` builds the provider without libde265 and drops the five HEIF suffixes; AVIF keeps working.

## Explorer thumbnail library: `glidemanaged.dll`

Not an optional decoder for the viewer (it has no `.glidecodec.json`, so `codecs.index.json` never lists it).
It is `src/Glide.ThumbnailCodecs`: Glide's managed decoders (camera RAW previews, EXR, DICOM/NIfTI/FITS/PFM,
ORA/KRA/PDN/XCF, KTX/KTX2/PVR/ASTC, ZIP PSD/PSB) compiled from the viewer's own source files into a NativeAOT
DLL that exports the same ABI v2, so the Explorer thumbnail provider can load it exactly like `glidecodecs.dll`
(lazily, SHA-256-pinned at build time, from this folder only; see `../docs/explorer-thumbnails.md`). `build.cmd`
republishes it on every build, before the provider is built, and ships it in `dist\codecs`.
